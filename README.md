# 趋势跟踪策略因子深度评估

> 七份因子深度评估报告（`reports/`）及其完整复现代码（`code/`）。
> 2026-10-19 ~ 2026-10-20 由一名基础数学在读博士生独立完成。
> 本仓库只含代码与报告成品，**不含任何行情/选股池数据文件**（见下文"数据依赖"）。

## 研究缘起与历程

这个项目的起点是威科夫（Wyckoff）的交易思想。我认同其"突破—回踩—确认"的结构化趋势观：**不买强势突破的顶点，而买趋势确立后的第一次回调确认**——回调不是趋势的终结，而是更好的介入点。

整个研究按这个直觉逐层展开、逐层证伪：

**第一步：B1（倒车/多空复合信号）。** 第一个研究对象。回测后数据显示全截面 IC、RankIC 均不好（六项全负）。但我不认为这说明微观经济原理失效了——"正在走趋势的股票回调是好的上车机会"这一判断，在后续的机制分层与风格归因中得到了支持（低 β、强势回调的风格桶本身有正收益）。**指标不好，是因为复合得太多了**：B1 是多条件叠加的复合信号，条件一多，样本被稀释、每个子条件的贡献也无法单独归因。

**第二步：B1 的确认信号 B2。** 效果同样不好。归因后我的判断是：超卖/确认类指标最终选出来的，往往是"趋势启动后又走坏"的票——形态上满足确认条件，但趋势本身已经断了。

**第三步：转向更灵敏、浅回调的信号——搬砖（多空临界支撑）与补票（单针下20）。** 这才"勉强能用"：其中补票是六信号中唯一在风格中性化后仍有显著正残差 alpha、且样本外验证期存活的信号（+0.75%/20日，验证期 +0.45%）。

**同时**，我也检验了威科夫框架下的两个标准买入形态——突破追入（bp1）与均线回踩（bp2），以及把介入点从"突破后回踩"再前移到"突破前波动压缩"的 d4 伏击因子。

**最后**，我单独研究了卖出信号（出场侧专项，成果另行整理）——进场逻辑只有配上出场逻辑才构成闭环。

由此形成了一个比较基础但闭环的趋势跟踪策略：入场用灵敏浅回调信号，出场用单独的卖出机制。

## 研究方法与严谨性

方法论上没有自己发明什么——我查了量化业内的通行做法（卖方金工研报的因子有效性检验框架、Barra/MSCI 风险模型的风格归因思路、以及从业者公开的因子评估规范），然后照着做的。以下是每一项做法对应的业内惯例，以及我执行到的程度：

**① 因子有效性检验协议（按卖方金工研报惯例）。** 信号层：分组统计（十分位 + 机制分层）、Pearson IC 与 RankIC（h=5/10/20 衰减曲线）、ICIR、正 IC 占比；组合层：月度 cohort 回测 + 日频 NAV，多档止损敏感性（不止损/8%/12%/15%）、夏普、最大回撤、月度胜率，对照同宇宙等权基准；稳健性：OFAT（one-factor-at-a-time）参数敏感性、市场 regime 分层、月度分段稳定性；微观机制：对手方分层（前涨幅/回撤/波动率）、持仓路径 MAE/MFE、入场滑点与跳空分解——回答"这个信号在买谁、持仓过程经历了什么"。

**② Point-in-time 纪律与口径统一。** 信号判定严格无未来函数：T 日收盘后可知，T+1 开盘入场，T+20 收盘出场，六个信号统一此口径以便横向可比；训练/验证按 2025-09-08 一刀切分，样本外结论只看验证期。过程中发现原始回测存在右截断偏差（right-censoring：无持有期限的长期持有口径使尾部收益来不及兑现，跨期比较失真），统一改为固定持有期口径重测并逐项登记。

**③ 风格暴露与中性化归因（Barra 式）。** raw 收益不等于 alpha。数据源没有市值/行业/基本面，做不了真 Barra，于是按 OHLCV 可得信息构造五个代理风格（ln 成交额、60 日 β、60 日动量、20 日波动、20 日反转）做日截面 OLS 中性化，把收益拆成"风格 β + 选股残差（abnormal return）"；显著性检验按日聚合（每日信号行残差均值作为观测），避免同日截面相关对 t 值的膨胀——对应 Fama-MacBeth 式的时间序列聚合思路。结论由此改写：B1/B2/搬砖的边际全是风格 β，只有补票在中性化后仍有显著正残差。

**④ 换手、持仓结构与收益时序。** 换手率（日度新开+平仓/日均持仓）、持仓重叠率、信号粘性 P(sig[t+1] | sig[t])、NAV lag-1 自相关——用于判断成本可行性（0.30% 往返费率摊销）与日收益是否存在可利用的时序结构。

**⑤ 偏离登记与失效披露。** 所有口径让步、数据源局限、语义限制逐项登记为 D1–D43，附在每份报告的"偏离登记"章；样本外失效不藏——系统在 2026-01 起样本外失效，衰减机制定位为止损阈值与标的波动率失配（8% 止损恰卡在 20 日最大回撤中位数 −8.9% 上），报告里主动披露并归因。

### code/ 命名约定（按流水线分四段）

| 段                                                            | 脚本                                                                                                                                                | 作用                                                                                                                                                        |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 特征复刻 `*_prep.py`                                           | b1/b2/bp1/bupiao/banzhuan/bp2                                                                                                                     | 从 K 线库逐行复刻信号计算，产出 `*_features.pkl`（含 OHLCV 原始阵列 + 信号布尔）                                                                                                   |
| ② 校准验证 `*_verify*.py` / `bp1_crosscheck.py` / `bp1_diag*.py` |                                                                                                                                                   | 截断模式调用原引擎逐条比对（100% 校准）；diag1-6 是校准过程中的调试脚本，保留供审计                                                                                                          |
| ③ 五项检验 `*_analysis*.py`                                      | 每信号：signal（信号层分组/IC）/ port（组合层止损档/cohort）/ robust（稳健性）/ micro（微观机制/对手方/持仓路径）；bupiao_gate.py 为补票三重硬门禁；d4_ambush.py + d4_full_analysis.py 为 d4 独立因子 | 产出 `*_results.json` / `*_nav_equity.json`                                                                                                                 |
| ④ 报告生成 `*_report.py`                                         | 每信号一个                                                                                                                                             | 读 results JSON 生成独立 HTML（内嵌 SVG 图表，无外部依赖）；自动注入 `healthcheck_chapter` 附章                                                                                   |
| 因子体检 `factor_healthcheck.py` + `healthcheck_chapter.py`      |                                                                                                                                                   | 六信号统一补全：全截面 Pearson IC/RankIC（h=5/10/20）、五代理风格暴露、日截面 OLS 风格调整 alpha（**按日聚合 t 为主口径**）、换手/持仓重叠/信号粘性、NAV lag-1 自相关。报告脚本依赖其产物 `healthcheck_results.json`，须先运行 |
| 出 PDF `print_pdf.py`                                         |                                                                                                                                                   | Edge headless 打印（Windows 专用；SRC 字典登记各报告）                                                                                                                  |

```bash
pip install -r requirements.txt   # 仅需 numpy + scipy，Python 3.10+（实测 3.13）

# ① 特征（需数据就绪，见下）
python b1_prep.py && python b2_prep.py && python bp1_prep.py && \
python bupiao_prep.py && python banzhuan_prep.py && python bp2_prep.py
# ② 校准（穿插在 prep 内或单独跑）
# ③ 五项检验（每信号一组）
# ④ 因子体检（报告脚本的前置依赖）
python factor_healthcheck.py      # 约 5-6 分钟，产出 healthcheck_results.json
# ⑤ 报告
python b1_report.py && python b2_report.py && python bp1_report.py && \
python bupiao_report.py && python banzhuan_report.py && python bp2_report.py && python d4_report.py
# ⑥ PDF（可选，Windows + Edge）
python print_pdf.py b1   # b2 / bp1 / bupiao / banzhuan / bp2 / d4 同理
```
